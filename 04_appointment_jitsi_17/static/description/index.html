03/06 Features Eight features, in plain words

Everything it does

Eight things it actually does

No screenshots in this section, on purpose — each feature names the exact Odoo field, method or template behind it instead, so you can check the claim against the source rather than against a picture. The recording at the top of the page shows the setup running end to end.

01

One switch, in the settings page you already know

The module adds a Jitsi Configuration block to Settings → Calendar, right under the Google Calendar sync you have already seen. Two controls, no separate menu, no wizard.

  • Jitsi Configuration — the master switch for the database
  • Company — whose name appears in the room address
  • The Company field only appears once the switch is on, so there is nothing to misconfigure
  • Stored as standard Odoo system parameters, so it survives upgrades
02

A different room for every single meeting

Each event gets its own 32-character random token, and the room address is built from it. Two meetings never land in the same room, so last month's participants cannot wander into today's call.

  • Format: https://meet.jit.si/<Company>/<Company>-<token>
  • The token is a version-4 UUID in hexadecimal — 32 characters, not guessable
  • Company names with spaces or accents are made URL-safe automatically
  • The address is stored in a real field, jitsi_link, so you can put it in a list view, a report or an automation
03

The Join button you already use — it just opens Jitsi

No new button, no new habit. Odoo's own video-call field is filled with the Jitsi room, so the standard Join action on the meeting form takes everyone straight there, in a new tab.

  • Works from the meeting form, the calendar view and the invitation
  • Guests do not need an Odoo account, and do not need an Odoo login screen
  • Participants can open it in the Jitsi Meet app on iOS or Android instead of a browser
  • The address is a plain URL — forward it in WhatsApp, in Slack, on paper
04

The room address is in the e-mail Odoo already sends

This is the part people forget and the part that actually saves the meeting. The module extends two of Odoo's own e-mail templates with a How to Join block, so the room travels with the invitation instead of in a follow-up message nobody reads.

  • Extends appointment.appointment_booked_mail_template — the booking confirmation
  • Extends calendar.calendar_template_meeting_update — the meeting invitation and update
  • Falls back to Odoo's standard video-call line if an event has no Jitsi room, so no e-mail ever goes out broken
  • No new templates to maintain and nothing to re-brand: your existing e-mail layout is untouched
05

Website bookings are covered, not just internal meetings

When a visitor books a slot through Odoo Appointment on your public website, the event Odoo creates goes through exactly the same path. The room is ready before the confirmation page finishes loading.

  • Works on every appointment type, resource or staff-based
  • Works for paid appointments as well as free ones
  • The visitor never sees Odoo — they see your booking page and then a Jitsi room
  • Nothing to configure per appointment type

And three more

Control, exceptions and the way back out

The three features nobody advertises and everybody eventually needs.

06

An escape hatch for the meetings that need one

Every event carries an is_jitsi field, and two callable methods sit next to it: generate_jitsi_link() issues a room, clear_jitsi_link() drops the meeting back to Odoo's own video call. Wire either one to a server action or an automation rule and you have per-meeting exceptions without forking the module.

Be clear on what this is: the module ships no checkbox for it on the meeting form. This is a hook for whoever administers your Odoo, not a control your end users will find. If you want it on the form, it is a one-line view change — ask us, or add the field yourself.

07

Recurring meetings get one room each

Set a meeting to repeat weekly and every occurrence is issued its own token. Nobody joins the wrong week, and you do not have to remember to refresh anything between occurrences.

08

Change your mind and nothing breaks

Untick the global switch and new meetings go back to Odoo's built-in video call, immediately, with no migration and no cleanup. Uninstall the module and Odoo removes the two fields it added — it added nothing else to remove.

Under the bonnet

What it actually adds to your database

Short list, on purpose. A module that touches little is a module that breaks little on your next Odoo upgrade.

Two fields on calendar.event

jitsi_link (stored text, copied when you duplicate an event) and is_jitsi (boolean, off by default). That is the entire data footprint.

Zero new models

Everything is an inheritance of calendar.event and res.config.settings. No new tables, no new menus, no new security groups.

Zero new access rules

Whoever can see a meeting today can see its room address. Your existing Odoo permissions are the permissions.

No API key and no outbound call

A Jitsi room comes into existence when somebody opens its address. Odoo therefore only has to compose the address — there is no API to authenticate against, no key to rotate, no rate limit to hit and no service that can be down at the moment you save a meeting.

Two methods you can call yourself

generate_jitsi_link() issues a fresh room, clear_jitsi_link() drops back to Odoo's own. Wire either one to a server action or a scheduled action without writing a module.

13 automated tests

Shipped inside the module and runnable with Odoo's own test runner, against Odoo 17 Enterprise on PostgreSQL 15. You can verify the behaviour on this page yourself.

LGPL-3, source included

Roughly 150 lines of readable Python. Read it, fork it, extend it. There is no obfuscated blob and nothing phones home.

English and French included

The module ships an English README and a French LISEZMOI. Field labels follow your Odoo interface language.

04/06 Why The objection, answered head-on

The obvious question

“Odoo 17 already has a video call. Why would I add this?”

Fair, and the honest answer is: if Odoo Discuss is where your meetings already happen, you do not need this module. Install it when the video tool your team actually uses is Jitsi — because then Odoo is quietly working against you four times a day.

Two video products, depending on where the meeting was booked

Odoo sends a Discuss link. Your team sends a Jitsi link. Participants get both and pick wrong.

One room, whatever created the meeting

Website booking, internal calendar entry, recurring stand-up — all of them come out as Jitsi. One tool, one habit.

Guests join Odoo Discuss in a browser tab

Your guest is not going to install the Odoo app to take one call, so they join in a mobile browser — and a client on a train notices.

Guests join in the Jitsi Meet app

Jitsi Meet is a free native app on iOS and Android. The link from your Odoo e-mail opens straight into it.

The video runs on your Odoo server, whether you planned that or not

The call is tied to the machine running your ERP. Where the media goes is decided for you.

The video runs wherever Jitsi runs

Public meet.jit.si today. Your own Jitsi server, in your own country, once you point the address at it — a one-line change Doodex can make for you.

Somebody pastes the real link in by hand

And they do it after Odoo already sent the confirmation e-mail, so the room lives in a second message the guest has to go find.

Nobody pastes anything, ever

The room is in the field, on the Join button and inside the confirmation e-mail before anyone thinks about it.

05/06 FAQs Thirteen real questions

Questions we actually get

Thirteen questions, answered without hedging

Including the four whose honest answer is “no”.

Do I need Odoo Enterprise, or will this run on Community?

You need Enterprise. The module depends on Odoo's appointment app, which ships only with Odoo Enterprise and Odoo Online. On Community, installation will fail with a missing-dependency error rather than half-working. If you are on Community and only need Jitsi rooms on ordinary Calendar meetings, write to us — that is a smaller module and we are interested in whether people want it.

Does it work on Odoo 18 or Odoo 19?

Not yet. This is a 17.0 module and it is only published for 17.0. Odoo 18 and 19 are on the roadmap in the Releases section below, without a promised date, because we would rather ship late than list a version that does not exist. If you are on 18 or 19 and want this, tell us — demand is how we order the roadmap.

Do participants need a Jitsi account to join?

Your guests need no account — they open the address in a browser or the Jitsi Meet app, type a display name, and they are in.

But on the public meet.jit.si there is one catch worth knowing up front: the conference does not actually start until a signed-in moderator joins. A guest who clicks the link before anyone else sees a holding screen telling them so, and waits. The moderator sign-in is free and one time per browser (Google, GitHub or Facebook) — a policy Jitsi introduced in August 2023. In practice whoever hosts the meeting signs in once, and everybody else just clicks the link.

On a Jitsi server you run yourself, none of this applies — no sign-in, no moderator gate, no third party in the middle. It is the strongest argument for self-hosting, and it is the first item on our roadmap.

Can I point the rooms at my own Jitsi server instead of meet.jit.si?

Not from Settings in this version. The base address https://meet.jit.si is fixed in the code. It is a single line, so the change is genuinely small — it is on the roadmap as a proper setting, and in the meantime Doodex can make the change and set up the Jitsi server as a service. Book the 30 minutes above and we will tell you what it costs before you commit to anything.

What happens to meetings that already exist when I install it?

They keep whatever video address they have now. The module does not go back and rewrite your history. To bring existing meetings across, call generate_jitsi_link() on them from a server action — select the records in the list view and run it. There is no per-meeting button for this out of the box; see the note on Feature 06.

Can I keep some meetings on Odoo's built-in call?

Yes, but not from the meeting form. Each event has an is_jitsi field that overrides the global default, and clear_jitsi_link() puts a single meeting back on the standard Odoo Discuss link. Neither is exposed as a checkbox out of the box, so exceptions are set through a server action, an automation rule, or by adding the field to your own form view. If per-meeting control matters to you, say so — putting it on the form is a small change.

How private is the room address?

Each room name contains a fresh 32-character random token, so it is not something anyone can guess or enumerate. But treat it the way you treat any meeting link: whoever holds the address can join the call. If a meeting is sensitive, set a room password in Jitsi once you are inside, or enable the lobby — both are Jitsi features and neither needs Odoo. Inside Odoo, the address is visible to exactly the people who can already see the meeting.

Does it change the e-mails Odoo sends?

Yes, two of them. It extends Odoo's own appointment.appointment_booked_mail_template (the booking confirmation) and calendar.calendar_template_meeting_update (the meeting invitation and update) with a How to Join block. Your layout, branding and wording are otherwise untouched, and if an event has no Jitsi room the block falls back to Odoo's standard video-call line. Note that these are overrides of core templates: if you have already customised those two templates yourself, review them after installing.

Does it work with recurring meetings?

Yes, and each occurrence gets its own room. That is deliberate: a single reused room means last month's participants can walk into this month's call. If you would rather one room served a whole series, that is a small change — ask us.

We run several companies in one database. Does that work?

Partly, and here is the limit. The Company whose name goes into the room address is a single setting for the whole database, not one per company. So the meetings work fine across companies, but every room is named after the one company you picked. Per-company naming is on the roadmap. If you need it now, say so and we will scope it.

Where does our meeting data actually go? What about GDPR?

Odoo stores only the text of the room address — no recordings, no participant list, no video, no audio. The call itself never passes through your Odoo server at all: it flows through whichever Jitsi instance the address points at.

Today that address points at the public meet.jit.si, operated by 8x8, so their terms and their data handling apply to the call. If your compliance position requires the video to stay inside your own infrastructure or a specific jurisdiction, self-host Jitsi — that is the whole reason self-hosting is the first item on our roadmap, and it is a service Doodex provides.

What happens if I uninstall it?

Odoo removes the two fields the module added, jitsi_link and is_jitsi, and the two e-mail template overrides revert to Odoo's originals. There are no new tables, no new access rules and no leftover menus, because the module never created any. Existing meetings keep whatever value is currently in Odoo's own videocall_location field — if that is a Jitsi address you no longer want, clear it or let Odoo recompute it.

It is free. So what is in it for Doodex?

Straight answer: this module is how you meet us. Doodex is an Odoo partner — we do implementation, customisation, migration and hosting, including Jitsi hosting. A free module that solves one problem properly is a better introduction than an advert. Install it, never contact us, and that is a perfectly good outcome; the licence is LGPL-3 precisely so that is a real option and not a trap.

Every version, dated, including the fixes we are not proud of

The quiet question behind every free module is “will this still be maintained in a year?”. A changelog is the only honest answer to it, so this one stays on the page and gets a new entry every time the module changes.

17.0.1.1.0Current release
  • FIXThe room address now really appears in the confirmation e-mails. The template file was never registered in the module manifest, so Odoo had never loaded it and both e-mail overrides were silently dead. This was the module's headline feature and it had not worked since the first release.
  • IMPThe per-event is_jitsi field is now honoured. Previously the global setting applied to every event in the database regardless of the field's value. Note that the field still has no checkbox on the meeting form — it is driven from a server action or an automation.
  • FIXTurning the global setting off now really turns Jitsi off. The stored value was being read as text, and any text counts as “on”, so unticking the box left the integration running.
  • FIXRecurring meetings now get their own room per occurrence. Odoo creates recurrences in a batch, and the batch path skipped room creation entirely.
  • FIXCompany names containing a space or an accent now produce a valid address. Doodex Group used to put a literal space inside the URL.
  • IMPRemoved the startup warning Odoo printed on every install about the module not creating records in batch.
